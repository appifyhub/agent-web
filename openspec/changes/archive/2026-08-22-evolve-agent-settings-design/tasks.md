## 4. Milestone 4 — Provider Access

- [x] 4.1 Audit the base classes of every shadcn primitive this slice will restyle, before writing any override, and record what each one already asserts.
  - **Why.** A shadcn base class encodes assumptions about the layout it was generated for, and those assumptions are usually expressed with higher specificity than a plain utility passed through `className`. When a redesign contradicts one, the base silently wins and the symptom appears somewhere other than the cause. This happened four times in Milestone 3, each costing several review rounds: `AccordionItem`'s `border-b last:border-b-0` assumes a divided list and stripped the bottom border from the last card; `DrawerContent`'s `data-[vaul-drawer-direction=bottom]:rounded-t-lg` and `max-h-[80vh]` are attribute selectors that outranked plain `rounded-t-3xl` and `max-h-[85vh]`, so both overrides were dead; `SelectItem`'s absolutely positioned indicator forced a padding reserve that pushed a sibling control inward, which no margin value could fix; and `CardHeader`'s `[.border-b]:pb-6` is a variant `tailwind-merge` cannot reconcile with `py-0`, so it beat the consumer's intent once the underlying utility started compiling.
  - **How.** For each primitive, read its base `cn(...)` and list the declarations that carry a pseudo-class, attribute, or variant selector — those are the ones that outrank a plain utility. Then either match that specificity, cancel the declaration in its own group (`[.border-b]:pb-0`), or restructure so the conflict cannot arise (moving `SelectItem`'s indicator into flow removed the padding reserve and every margin that compensated for it). Prefer restructuring: needing a magic number to align two adjacent elements is evidence the structure is wrong, not the value.
  - **Scope for this slice.** Provider access exercises Input, Alert, Dialog, Card, and Button. Confirm the actual set against the route before starting, and treat `tailwind-merge` as unable to reconcile variant-prefixed utilities with their plain counterparts — verify a merge with `cn()` rather than assuming it resolved.
